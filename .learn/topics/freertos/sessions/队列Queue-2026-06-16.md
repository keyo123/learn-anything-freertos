## Positioning

`队列 (Queue)` 位于 FreeRTOS 知识树的 **3. 队列与 IPC** 分支下。在掌握了任务管理与信号量同步后，队列是任务间传递数据和复杂信息交互的基石。

## Analogy

我们将队列比作一个**“带格子的自动传送带”**或**“快递自提柜”**：
* 假设任务 A 是“工厂生产者”，任务 B 是“质检员（消费者）”。如果让他们直接“手递手”传零件，如果质检员很忙，生产者就只能停下手中的工作干等。
* 引入一条带固定格子（深度）的“传送带”（队列）：
  * 只要传送带上还有空格子，生产者 A 就可以把零件放到传送带上，然后立刻回去生产下一个，不用干等。
  * 质检员 B 只要看到传送带上有零件，就拿下来检测。如果传送带空了，B 就会在传送带旁打盹（进入阻塞状态挂起）。
  * 一旦生产者 A 放上新零件，打盹的 B 会立刻被叫醒（唤醒）并开始工作。

## Core Mechanism

1. **先进先出 (FIFO)**：默认情况下，FreeRTOS 队列遵循 FIFO 规则。先写入的数据先被读取。不过 FreeRTOS 也支持“插队”操作（如 `xQueueSendToFront`）。
2. **值传递 (Copy by Value)**：
   * 发送数据到队列时，FreeRTOS 会把数据**完整拷贝**一份存入队列的内存中。
   * **好处**：安全。发送任务即使是一个局部变量，发送完之后该局部变量被销毁或修改，也不会影响队列中已保存的副本。
   * **代价**：拷贝大数据时 CPU 消耗高。若需要传输大结构体，应采用**引用传递（传递指针）**，但需保证指针指向的物理内存生命周期安全。
3. **阻塞与唤醒机制 (Blocking on Queue)**：
   * **写阻塞**：如果队列满了，写入任务可以选择阻塞等待（可设置超时时间 Timeout）。一旦有读任务取走元素，写任务立刻被唤醒写入。
   * **读阻塞**：如果队列空了，读取任务可以选择阻塞等待。一旦有写任务送入新数据，读任务立刻被唤醒读取。

## Underlying Memory Structure & Blocking Principles (2026-06-16 深入学习)

### 1. 底层内存分布 (Ring Buffer)

当调用 `xQueueCreate` 时，FreeRTOS 会在系统堆 (Heap) 上分配**一大块连续的内存**。这块内存包含两个主要部分：
1. **队列控制块 (Queue Control Block, `Queue_t`)**：存储队列的全部控制信息（链表、指针等）。
2. **环形缓冲区 (Ring Buffer)**：紧贴在结构体之后的一整块连续的存储区，总字节大小为 `uxQueueLength * uxItemSize`。

底层的存储控制指针模型如下：
```text
┌────────────────────────────────────────────────────────┐
│              Queue_t 控制结构体（句柄）                  │
├────────────────────────────────────────────────────────┤
│ - pcHead ──────┐ (指向存储区头部)                       │
│ - pcTail ──────┼──────────────┐ (指向存储区尾部+1)      │
│ - pcWriteTo ───┼──────────┐   │ (下一个待写位置)        │
│ - pcReadFrom ──┼──────┐   │   │ (最近一次读取的位置)     │
└────────────────┼──────┼───┼───┼────────────────────────┘
                 ▼      ▼   ▼   ▼
                 ┌───┬───┬───┬───┬───┐
环形存储区 (RAM)  │ 0 │ 1 │ 2 │ 3 │ 4 │  (例如 Length = 5)
                 └───┴───┴───┴───┴───┘
```
* **环形边界处理**：每次写入或读取数据时，`pcWriteTo` / `pcReadFrom` 会向后移动 `uxItemSize` 个字节。当指针到达底部的 `pcTail` 时，FreeRTOS 会自动将其绕回重置到 `pcHead`，从而实现无缝的环形存储。

### 2. 双向阻塞与唤醒原理

在 `Queue_t` 控制块内部，有两个极其关键的**任务等待链表**：
* `xTasksWaitingToSend`：**写阻塞任务列表**。当队列已满、任务尝试写入但超时未到时，该任务节点挂在此列表上。
* `xTasksWaitingToReceive`：**读阻塞任务列表**。当队列为空、任务尝试读取但超时未到时，该任务节点挂在此列表上。

#### 🔄 唤醒机制运转过程：以任务 A 读空队列为例

1. **进入读阻塞**：
   * 任务 A 调用 `xQueueReceive(..., portMAX_DELAY)`，底层检测到当前没有数据（`uxMessagesWaiting == 0`）。
   * 调度器将任务 A 从系统“就绪列表 (Ready List)”中移除。
   * 将任务 A 插入到该队列控制块的 `xTasksWaitingToReceive` 链表中，同时插入系统“延时/阻塞列表”。此时任务 A **挂起，完全不消耗 CPU**。
2. **数据送达与唤醒**：
   * 任务 B 调用 `xQueueSend(...)` 往队列写入了一个数据，底层将数据拷入环形缓冲区，且 `uxMessagesWaiting` 加 1。
   * 写入成功后，FreeRTOS 会检查该队列的 `xTasksWaitingToReceive` 等待链表。
   * 发现任务 A 正在等待。FreeRTOS 会立即**把任务 A 从 `xTasksWaitingToReceive` 链表和系统的阻塞列表中移除**，并重新放入“就绪列表”。
3. **抢占切换**：
   * 如果被唤醒的任务 A 优先级高于当前执行的任务 B，调度器会立刻触发一次上下文切换（Context Switch），任务 A 瞬间获得 CPU 并抢占运行。

## Code Example

```c
/* 定义一个队列句柄 */
QueueHandle_t xQueue = NULL;

/* 假设我们传递一个简单的消息结构体 */
typedef struct {
    uint32_t ulValue;
    char cSourceID;
} Message_t;

void vAppInit(void) {
    /* 创建队列：深度为 5，每个元素大小为 Message_t 的字节数 */
    xQueue = xQueueCreate(5, sizeof(Message_t));
    if (xQueue == NULL) {
        // 队列创建失败，通常因为堆内存 (Heap) 不足
    }
}

/* 生产者任务 */
void vSenderTask(void *pvParameters) {
    Message_t xMsg = { .ulValue = 100, .cSourceID = 'A' };
    for (;;) {
        /* 发送消息到队尾，阻塞等待时间为 100 毫秒 */
        if (xQueueSend(xQueue, (void *)&xMsg, pdMS_TO_TICKS(100)) == pdPASS) {
            // 发送成功
        } else {
            // 队列已满，且超时 100ms 仍未腾出空间
        }
        vTaskDelay(pdMS_TO_TICKS(500)); // 延时 500ms
    }
}

/* 消费者任务 */
void vReceiverTask(void *pvParameters) {
    Message_t xReceivedMsg;
    for (;;) {
        /* 从队头接收消息，无限期阻塞等待（portMAX_DELAY），直到有数据送达 */
        if (xQueueReceive(xQueue, &xReceivedMsg, portMAX_DELAY) == pdTRUE) {
            // 成功收到消息，可以对其进行处理
            // printfSafe("Received value: %d from sender: %c\r\n", 
            //            xReceivedMsg.ulValue, xReceivedMsg.cSourceID);
        }
    }
}
```

### 代码解析：
* **`xQueueCreate`**：动态在 Heap 上分配队列所需的控制块和元素存储空间。
* **`xQueueSend`**：将 `xMsg` 的内存数据完整拷贝进队列。
* **`xQueueReceive`**：从队列队头拷贝出数据到 `xReceivedMsg` 缓存区，并将其从队列中移除。

## Common Misconceptions

* **误区一：队列里只能存简单类型**  
  * 实际上，队列能存任何固定大小的数据结构，甚至是指针。核心在于创建时必须指定正确的 `uxItemSize`。
* **误区二：在中断中直接调用 `xQueueSend` / `xQueueReceive`**  
  * 绝对不行！中断中必须使用 `xQueueSendFromISR` / `xQueueReceiveFromISR`。而且中断安全 API 绝不允许阻塞（Timeout 必须为 0），否则会导致单片机异常。

## Quick Summary

- **核心定位**：FreeRTOS 任务间数据传递的 FIFO 基础通道，基于值传递（内存拷贝）。
- **阻塞机制**：支持读写双向阻塞等待，超时机制可配置，由调度器自动挂起 and 唤醒任务。
- **安全边界**：中断中必须使用 `FromISR` 版本，避免在队列中传递生命周期不可控的局部指针。
