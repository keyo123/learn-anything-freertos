## User's Answers & Explanations
1. **中断安全 API 的“特殊内幕”**
   - `xEventGroupSetBitsFromISR()` 内部并不会在中断服务程序（ISR）中直接设置标志位。
   - 它是向 FreeRTOS 的定时器后台任务（Daemon Task / Timer Task）发送一条置位命令消息，将实际修改位的操作交给该任务异步完成。
   - 这是因为设置事件组的位可能会唤醒多个等待的任务，这涉及复杂的调度逻辑、优先级判定和任务切换，其执行时间是不确定的（Non-deterministic）。在要求极高确定性的 ISR 中不允许进行这种时间不确定的操作。
2. **自动清除（xClearOnExit）的精确范围**
   - 仅清除我们在 `uxBitsToWaitFor` 参数中指定的那些标志位，其余未在等待掩码中的标志位将保持原样。
3. **同步屏障（Sync Barrier / Rendezvous）**
   - 用于解决多个并发任务必须相互等待以协同对齐的场景。
   - 例如：Worker1、Worker2、Worker3 在进行初始化时，由于它们的第一阶段工作耗时不同（各自延时 1s、2s、3s），只有当全部 Worker 完成第一阶段准备并到达屏障点后，它们才允许同时踏过屏障，一起跨入第二阶段。
4. **与任务通知的取舍**
   - 任务通知是“一对一”的（保存在目标任务的 TCB 内），一旦需要实现“一对多”的广播同步（即一个事件位置位后同时唤醒多个任务）或者“多对多”的同步（如 Sync Barrier），就必须使用事件组。
