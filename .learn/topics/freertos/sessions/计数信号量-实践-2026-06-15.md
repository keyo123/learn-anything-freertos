## Positioning

计数信号量位于 **同步机制 → 计数信号量** 分支。它常用于两种典型场景：
1. **事件计数**：每次事件发生时 `Give` 信号量（计数加 1），处理任务 `Take` 信号量（计数减 1）。这种情况下初始值为 0。
2. **资源管理**：信号量计数值代表可用资源的数量。任务需要获取资源时 `Take`（计数减 1），释放资源时 `Give`（计数加 1）。这种情况下初始值等于资源的最大总数。

## Analogy

想象一个拥有 3 个车位的停车场：
* **初始化**：门口的显示屏显示剩余车位为 3（计数器初始值 = 3）。
* **驶入车位 (Take)**：当一辆车（任务）驶入停车场时，必须刷卡获取一个车位，显示屏数值减 1（3 -> 2 -> 1 -> 0）。当显示屏为 0 时，后来的车必须在门口排队等待，直到有车出来。
* **驶离车位 (Give)**：一辆车驶出停车场时，刷卡释放车位，显示屏数值加 1（0 -> 1 -> 2 -> 3）。门口排队的第一辆车被允许驶入。

二值信号量就像是“只有一个车位”的特殊停车场（最大值为 1，非 0 即 1，类似于旗帜）。而计数信号量则支持管理多个同类资源。

## Core Mechanism

API 接口：
* **创建**：`xSemaphoreCreateCounting(uxMaxCount, uxInitialCount)`
  * `uxMaxCount`：信号量能达到的最大计数值。
  * `uxInitialCount`：信号量创建时的初始计数值。
* **获取 / 释放**：与二值信号量相同，依然使用 `xSemaphoreTake()` 和 `xSemaphoreGive()`。
* **获取当前计数值**：`uxSemaphoreGetCount(xSemaphore)`。

## Code Example

我们将在 [demo_semphr.c](file:///C:/Users/24212/Desktop/za/study/learn-anything/01-FreeRTOS-LED/User/demo_semphr.c) 中实现这个经典的“停车场车位限流”模型。

```c
static SemaphoreHandle_t xParkingSem = NULL;

static void vTaskCar(void *pvParameters)
{
    int car_id = (int)pvParameters;
    
    for (;;)
    {
        printfSafe("[Car %d] 正在等待车位...\r\n", car_id);
        
        // 尝试驶入停车场（占用一个车位资源）
        if (xSemaphoreTake(xParkingSem, portMAX_DELAY) == pdTRUE)
        {
            printfSafe("[Car %d] 🟢 成功驶入，剩余车位: %d\r\n", 
                       car_id, (int)uxSemaphoreGetCount(xParkingSem));
            
            // 模拟停车 1~2 秒
            vTaskDelay(pdMS_TO_TICKS(1000 + (car_id * 200)));
            
            printfSafe("[Car %d] 🔴 驶离停车场...\r\n", car_id);
            
            // 释放车位资源
            xSemaphoreGive(xParkingSem);
            
            printfSafe("[Car %d] 已经离开，当前空余车位: %d\r\n", 
                       car_id, (int)uxSemaphoreGetCount(xParkingSem));
            
            // 离开后等待一段时间再尝试重新停车
            vTaskDelay(pdMS_TO_TICKS(1500));
        }
    }
}
```

## Socratic Check & Discussion

* **Question**: 如果我们要利用计数信号量来实现一个**事件计数器**（例如：每来一个串口字节中断，计数器加 1，后台任务取走字节后计数器减 1），我们在创建这个信号量时，它的 `uxMaxCount` 和 `uxInitialCount` 分别应该设置为什么？为什么？
* **User's Answer & Discussion**:
  * `uxMaxCount` 应该设置为串口缓冲区的最大值（防止溢出）。
  * `uxInitialCount` 应该设置为 0。因为在系统刚启动时，缓冲区内没有任何未处理的事件（字节），只有当串口接收中断触发并 `Give` 信号量后，计数值才会增加，主任务才能 `Take` 成功并处理。
