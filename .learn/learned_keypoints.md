## 1. 任务创建与删除

### 💡 核心机制
* **动态内存分配**：`xTaskCreate()` 函数在堆（Heap）上自动为任务分配任务控制块（TCB）和任务堆栈。
* **堆栈高水位监测**：使用 `uxTaskGetStackHighWaterMark(NULL)` 监测**当前任务自启动以来历史最小空闲堆栈大小**（以“字/Words”为单位）。若返回 0 则表明堆栈已溢出；若余量过大则说明内存被浪费。
* **自我销毁**：任务调用 `vTaskDelete(NULL)` 标志着任务的生命周期结束，自我销毁并移出调度器。

### ⚠️ 避坑指南
* **空闲任务内存回收**：动态创建的任务在自我删除后，**其 TCB 和堆栈的物理内存回收是由空闲任务 (Idle Task，优先级 0) 异步完成的**。
* 如果系统里有一个优先级 $\ge 1$ 且没有阻塞延时（如 `vTaskDelay`）的死循环任务独占 CPU，会导致空闲任务被饿死，导致系统内存迅速耗尽并发生 Crash。

## 2. 中断安全 API

### 💡 核心机制
* **FromISR 后缀**：在中断服务程序（ISR）中，必须使用带 `FromISR` 尾缀的内核 API（如 `xSemaphoreGiveFromISR`）。
* **实时任务切换（Yield）**：
  * 中断安全 API 会带有一个参数 `BaseType_t *pxHigherPriorityTaskWoken`。当该调用唤醒了一个高优先级任务时，内核会将其修改为 `pdTRUE`。
  * 退出中断服务前，必须调用 `portYIELD_FROM_ISR(xHigherPriorityTaskWoken)` 强制触发挂起的中断（PendSV），使高优先级任务在退出中断的瞬间**立即抢占运行**，保证实时相应。
* **硬件优先级界限**：
  * `FromISR` API 仅能从物理优先级**等于或低于** `configMAX_SYSCALL_INTERRUPT_PRIORITY` 的中断中被调用（在 STM32 优先级组4下，中断抢占优先级数值必须 $\ge 5$）。
  * 优先级更高的硬实时中断不能调用任何 FreeRTOS API，但它们绝不会被内核延迟，响应极其迅速。

### ⚠️ 避坑指南
* **中断调用空指针防崩溃**：在中断中操作任务句柄（例如通过 `xTaskResumeFromISR` 唤醒任务）时，**必须提前进行非空校验**（如 `if (xTaskHandle != NULL)`）。如果对空句柄进行操作，会触发 FreeRTOS 内部的 `configASSERT` 导致系统崩溃挂起。

## 3. 递归互斥量

### 💡 核心机制
* **可重入锁**：允许同一个任务在不释放锁的前提下，**多次成功获取（Take）同一把锁**而不发生自我死锁。主要用于多层函数嵌套调用或递归函数保护共享资源。
* **嵌套计数器**：递归互斥量内部维护一个计数器。同一个任务 `Take` 了多少次，就必须配对 `Give` 多少次。
* **完全释放**：只有当该任务的释放次数与获取次数相等，计数器清零后，锁才会真正归还内核，其他就绪任务才能获取。

### ⚠️ 避坑指南
* **锁扣留饥饿**：如果获取了 3 次但只释放了 2 次，该锁将永远被此任务（即使此任务已经删除）扣留。此时其他尝试获取此锁的任务（如 `Observer` 任务）会被无限期挂起直至发生超时（Timeout）。

## 4. 计数信号量

### 💡 核心机制
* **资源池管理**：创建时定义最大容量和初始资源数 `xSemaphoreCreateCounting(uxMaxCount, uxInitialCount)`。
* **多资源控制**：每次 `Take` 使计数值减 1，每次 `Give` 使计数值加 1。当计数值为 0 时尝试 `Take` 的任务将进入阻塞。
* 典型应用场景为**停车场车位管理**或**生产者-消费者缓冲区资源控制**。

## 5. RTOS vs GPOS

* **RTOS (如 FreeRTOS)** 追求的是 **确定性（Determinism）**。调度算法为严格的优先级抢占式。它的临界区极短，在最坏情况下的响应延迟是微秒级且可预测的。
* **GPOS (如 Linux/Windows)** 追求的是 **高吞吐量（Throughput）和公平性（Fairness）**。内核中频繁存在非抢占区和自旋锁，即使将某个任务设为最高优先级，也无法保证微秒级的响应，容易发生不可靠的延迟抖动（Jitter）。

---

## 6. 任务通知 vs 二值信号量

* **任务通知（Task Notification）** 属于**一对一**同步。它的通知值直接存放在任务控制块（TCB）中，**无需创建额外的内核对象**。因此它的 **RAM 开销为零，速度快 45%**。
* **二值信号量（Binary Semaphore）** 属于**多对多/多对一**同步。它是一个独立的内核对象，允许多个任务阻塞等待同一个信号量。
